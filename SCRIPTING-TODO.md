# Scripting upgrades checklist

The scripting improvements we're working through, bash side and Python side. Whoever finishes an
item (a person or an agent) ticks its box and fills in its Notes: what changed, which tests and
docs cover it, and anything left out. An item is done only when the full test suite passes.

## Bash side

- [x] **1. `set` options**: `set -e`, `-u`, `-x`, `-o pipefail`, `+X` to turn one off, `set -o` to list, `set --` for the arguments
  - Done when: `-e` stops the current line, function, sourced file, rc or func (never the shell); `-u` stops on an unset variable; `-x` prints each line before it runs; tests, `man set`, docs
  - Notes: `set` builtin in commands/misc.py (SET_DOC, in SPECIAL_BUILTINS); `ctx.options` + `ctx.errexit_off` (tests, left of `&&`/`||`, `!`, and functions called from them). `-e`: `_Runner.check_errexit` raises `_Abort(reported=True, stops=True)`; `PipelineResult.stopped` tells `startup.source` to skip the rest of the file (one `✗ file:N … (set -e: …)` line); a piped block stops but its tail runs; `$( )` stops only itself. `-u`: `parser.UnboundVariable` -> `pipeline.UnboundError` ("NAME: unbound variable", status 1), stops like `-e`; `$1`.., `$#`, `$@`, `$?` exempt. `-x`: `+ words` per pipeline segment and for `x=1`, via write_stderr. `pipefail`: earlier segments record their status. funcs `_snapshot` keeps options. `set --` / `set a b` replace the args (a top-level frame when outside a function). Tests: tests/test_set_options.py. Docs: scripting/functions.md "Stop on errors with set -e", scripting.md, cheatsheet, funcs.md, startup.md, CHANGELOG. Not done: `x=$(false)` doesn't trigger `-e`; `$((unset))` isn't checked by `-u`; `-x` prints `+` (no `++` for nesting).
- [x] **2. `trap`**: `trap 'CMD' EXIT|INT|ERR`, `trap - SIG`, `trap` to list
  - Done when: an EXIT trap runs when its function, sourced file or func ends (at the prompt: when the shell exits); INT on Ctrl-C; ERR on a failing command; `exit` in rc checked; tests, `man trap`, docs
  - Notes: new shellcraft/traps.py (frame(), interrupted(), failed(), session_exit()); `trap` builtin in commands/misc.py (TRAP_DOC, SPECIAL_BUILTINS, `-p`, `-l`, `''`, `-`, names any case / SIG prefix / 0 / 2). `ctx.traps` frames: call_function (bash and `def`, EXIT runs before `local`s are put back), `source` builtin files, funcs. The rc file, startup/*.sc and a profile's rc use the session frame (`startup.source(session=True)`) so `trap EXIT` there runs when you leave, as in ~/.bashrc. EXIT at the prompt: Shell._goodbye (exit and Ctrl-D). INT: innermost INT trap, run once per Ctrl-C (marked on the KeyboardInterrupt), then the unit stops as before. ERR: _Runner.check_errexit, run_line's simple path, and the error paths of source / funcs.run / Shell._execute; respects errexit_off, no recursion (ctx.in_trap), `$?` restored; a failing function call doesn't run it twice (ctx.err_ran_at). Trap output in a non-live function goes into the function's output. `exit` in rc bug was real (ShellExit caught as "startup failed"): cli._interactive now ends cleanly with the code, running EXIT traps. Completion offers EXIT/INT/ERR. Tests: tests/test_trap.py. Docs: scripting/functions.md "Clean up with trap", funcs.md, startup.md, scripting.md, cheatsheet, CHANGELOG. Not done: INT at an idle prompt (only while a command runs); trap output in a non-live function interrupted by Ctrl-C is lost.
- [x] **3. `getopts`**: options for functions and funcs, like `backup -v -f notes.txt`
  - Done when: bash behaviour (`OPTARG`, `OPTIND`, `?` for unknown, leading `:` for silent), works in `def`; tests, `man getopts`, docs
  - Notes: new shellcraft/getopts.py (next_option(), fresh()); `getopts` builtin in commands/misc.py (GETOPTS_DOC, a normal stateful builtin, not special). Reads `ctx.positional[-1]` or the words after NAME; grouped `-vf X` and glued `-fX`; `--` is skipped; end: status 1, NAME=`?`. Unknown / missing value: NAME=`?`, OPTARG unset, `getopts: illegal option -- x` / `option requires an argument -- f` via write_stderr; leading `:` silent mode (`?`/`:` with OPTARG=letter). The place inside a group is `ctx.getopts_at` (OPTIND, pos), dropped when OPTIND no longer matches (so `OPTIND=1` restarts). call_function (bash and `def`) and funcs.run wrap in getopts.fresh(): OPTIND=1, the caller's back afterwards (after `local`s, so `local OPTIND` works). Also fixed: a bash `case` pattern can escape with `\` (`\?)` matches only `?`; script._unquote). In `case -py`, `"?"` is still a glob; docs say to use `_:`. Tests: tests/test_getopts.py. Docs: scripting/functions.md "Options like -v and -f FILE" (bash, silent, `def` Python style), funcs.md "Options", scripting.md, cheatsheet, CHANGELOG, help group. Not done: messages say `getopts:` (no script name); no completion (nothing obvious to offer).
- [x] **4. Check a script without running it**: `source -n FILE` and `func check NAME`
  - Done when: every problem is reported as `file:line: message` (unfinished blocks, bad indentation, unknown commands as warnings), nothing runs; tests, docs
  - Notes: New shellcraft/check.py (check_text, Report, a statement-tree walker) shared by `source -n` (builtins.py) and `func check` (commands/func.py, ACTIONS, USAGE, FUNC_DOC, completer). Reads like `source` (logical_lines, colon blocks), parse_script per command; an IndentError is reported and its line blanked so the rest is still checked; a block open at EOF is reported at its first line, then closed so the commands inside are checked too. Unknown commands are looked up like `_call` (file functions, ctx.functions, aliases incl. ones the file defines, builtins, modules, `command: yes` funcs, PATH via _resolve_system; "OS commands are off" and "module disabled" get their own warning; a top-level call before the file defines the function warns), and `$( … )` contents are checked too. Since logical_lines joins a block into one command, a problem inside it is placed by finding the word in the block's lines (a heuristic; a parse error falls back to the block's first line). Tests: tests/test_check.py. Docs: scripting/README.md (runnable example), startup.md, funcs.md, scripting.md, cheatsheet, man source / man func, CHANGELOG.
- [x] **5. Run a func from outside ShellCraft**: `shellcraft func run NAME ARGS`
  - Done when: no banner or prompt, rc/startup/profile loaded (unless `--no-startup`), output on stdout, errors on stderr, the func's status is the exit code; tests, docs
  - Notes: cli.py: `_parser()` split out of `_parse_args`; `_split_func` finds the first `func` that isn't an option's value (uses the parser's own option table, unique `--prof` prefixes too), so `shellcraft --profile work --no-startup func run deploy x` works; main() parses the part before, skips skel.seed, refuses --mcp/--mcp-http/--init/--role/--expose, and after the registry loads hands off to new shellcraft/func_cli.py. It builds a ShellContext with a UI on a plain Rich Console(stdout) (colours only on a terminal; not a TTY: to_text plain writes), ctx.emit = ctx.live, emit_error = one `shellcraft: msg` line on stderr, interactive = stdin.isatty() (read/input ask via prompt_toolkit only then), allow_system = --allow-system or system_commands. Startup as _interactive: profile enter_env, rc (session traps), startup/*.sc, profile run_rc, gated by --no-startup / --lite / the startup setting. No ✓ summary by default; `-v` prints it on stderr (least noise for cron). Exit: outcome.status; `exit N` -> N; unknown func 127; missing NAME / bad switch / -b / editing actions (new, edit…) 2; Ctrl-C 130; session EXIT trap always runs. Bonus: `shellcraft func list/show/check/path` run the builtin. Usage in --help epilog. Tests: tests/test_func_cli.py (12, incl. a real `python main.py` subprocess). Docs: funcs.md "Run a func from outside ShellCraft" (cron line, echo $?), command-line.md "Running a func", cheatsheet, man func, CHANGELOG. Note: rc output also goes to stdout (use --no-startup when the rc prints).

## Python side

- [x] **6. Python assignment**: `x = EXPR`, `count += 1` and the other `op=` forms, in `-py` blocks and `def`
  - Done when: works in colon and brace blocks and `def`; `x = 5` at the prompt is unchanged; tests, docs
  - Notes: new `Assign` statement (script.py), parsed in py mode only when the `=` has a space on a side (`x=5` stays the bash form) or the op is `+=` etc.; `NAME = input(…)` lines still go to run_input. The value goes through compile_condition (now takes `what`/`noun` for messages), so a bad value is a parse error that `source -n` / `func check` report. `run_assign` stores str(value) through the new `pipeline.set_variable` (shared with `x=1`: `set -x` trace, export), so `local` and def params work. `+=` with text on the right concatenates, else the current value is read as int, then float; unset name or non-number is reported, status 1 (ERR trap / `set -e` apply), the script goes on. `$( )` in the value is a parse error pointing at `x=$(cmd)`. Tests: tests/test_py_assign.py. Docs: python-style.md (Set a variable, while example, table), variables-and-input.md (Python style section), loops.md (counter), scripting.md, cheatsheet, CHANGELOG, FOR/WHILE/FUNCTION man pages; fixed stale "not inside blocks" input notes (READ_DOC, ask.py). Known: after a parse error inside a `def`, `source -n` reads the rest of the body as top-level lines (pre-existing), so it may warn about them.
- [x] **7. `def` return values**: `return EXPR`, and `add(1, 2)` inside Python code
  - Done when: as a command, 0-255 is the status, True/False are 0/1, anything else is printed; `$(add 1 2)` captures it; `total = add(1, 2)` and `if is_weekend(day):` work; tests, docs
  - Notes: `return EXPR` is Python only in py mode with a `def` as the innermost function (new `_Parser.in_def`; a bash function nested in a def, or a bash `if … fi` inside a def, keeps bash `return N`). Parsed with compile_condition into `Jump.tree`, so errors show in `source -n` / `func check`; `$(` in it is a parse error. `_Return` carries `value`; call_function split into `_run_function` (output, status, value) + `_returned()` mapping (bool → 0/1, None → 0, int 0..255 → status, else printed + newline after the echoed output). A bad return expression is reported and the call returns 1. Python calls: `evaluate(tree, names, call)` sets a ContextVar that `_eval` uses for names not in FUNCTIONS; `_Runner.call_function` runs the function (args str(), output captured, `$?` set) and gives the return value or the output with trailing newlines stripped. Unknown name → "NAME is not a function" at run time. `_vet` now allows any plain-name call except `_`-prefixed ones, so `open('x')` is now a run-time error instead of a parse error (test_script param moved to test_def_return; test_py_assign's open() case swapped for a lambda). Recursion uses MAX_FUNCTION_DEPTH (100), fine under Python's recursion limit. `$name` inside a returned string is not expanded (it's Python): docs use `day + ": rest"`. Assignment `x = f()` still only in blocks/defs, not at the prompt. Tests: tests/test_def_return.py. Docs: functions.md (new "Give back a value with return" and "Call a function from Python" under def), python-style.md functions, FUNCTION_DOC and IF_DOC-style condition page in builtins.py, scripting.md, cheatsheet, CHANGELOG.
- [x] **8. `try:` / `except [as NAME]:` / `finally:`**
  - Done when: a failing command or a Python error jumps to `except`; `finally` always runs, also on break, continue and return; brace form works in bash functions; tests, docs
  - Notes: indent.py: `try:` / `try -py:` (no flag needed) opens a "try" level; `except [as NAME]:` / `finally:` merge at its indentation (_MERGES) into `try -py { } except as NAME { } finally { }`; errors for a try with neither part, stray except/finally, except after finally, a second except/finally, `except ValueError:` (suggests `except:` / `except as status:`). script.py: `Try` statement, `_try` (with or without -py; bodies are py with -py or in py mode, else bash, so it works in bash functions; `try` followed by anything but `-py`/`{`/end stays a command; a brace `try { }` at the end of the text is incomplete so the prompt/sourced files wait for `except`). Runner: `_Runner.trying` (per runner, so function calls and `$( )` start at 0); check_errexit raises `_TryFailed` when trying and not in a test (same exemptions as set -e); a bad `return EXPR` too; `_Abort` (bad Python condition, set -u…) is caught only when there is an except (otherwise it keeps stopping the script after finally). except: NAME and `$?` = failing status, try status = except's last. No except: after finally the status is the failing one and check_errexit runs (ERR, set -e, or an outer try). finally always runs (try/finally, also break/continue/return/exit/Ctrl-C) and keeps `$?`. ERR: new ctx.try_handlers counter (traps.failed skips) while a body with an except runs, also inside functions it calls. check.py walks Try (walker + _nodes). highlight: try/except/finally keywords, `as` after except, and `else:`/`try:`/`except:`/`finally:` with the colon now count as keywords. `try` in KEYWORDS, KEYWORDS_HELP, `man try` (TRY_DOC). Tests: tests/test_try.py (45); test_usage allows "try". Docs: python-style.md "Handle errors with try" + table rows + indent messages, functions.md "Catch failures with try" (bash brace form), examples.md "A backup that always cleans up", scripting.md quick ref + section, cheatsheet, scripting/README.md, CHANGELOG. Left as is: a try used as an `if` condition doesn't jump (errexit_off, like set -e in bash); a piped block inside a try body only counts by its final status.
- [x] **9. `match` / `case`**: `match WORD:` with `case PATTERN:` arms
  - Done when: same matching as `case -py` (`"a" | "b"`, globs, `_`); tests, docs
  - Notes: indent.py: `match WORD:` / `match -py WORD:` (no flag needed, only as a `:` header; `match x`, `match(…)`, `match = …` stay commands) opens a "match" level → `case -py WORD {`; a bare name (`match choice:`) reads the variable (`$choice`), anything else is the word as typed. Arms go through new `_arm()`: in a match block they must be `case PATTERN:` ("match: each choice is case PATTERN: (for anything else: case _:)"); in a `case -py X:` block `case PATTERN:` is accepted too (the `case ` is stripped; a lone `case:` stays the pattern "case"); `case P if …:` guards are rejected ("no 'if' guards on a choice"; an `if` inside quotes is fine); one-line arms, `pass` in one too. Brace form (small script.py change): `match -py WORD { case P { … } … }`, or `match WORD {` inside a -py block (`_match_follows`, reuses `_case`); `_case_py` drops a leading `case ` from each arm, so `case -py` brace arms may use it too. `match` builtin stub (hidden, doc=CASE_DOC with a rewritten "Python style: match" section), in KEYWORDS_HELP and highlight KEYWORDS (the `match()` condition function is never a bare word, so it isn't mis-highlighted); test_usage allows "match". Prompt block mode and `source -n` work unchanged (tested). Follow-up fixes: (a) indent._is_python: a condition starting with `[`, `[[`, `test` (or `!` + one) is a command, so `if -py [ -f x ]:` / `while -py [ … ]:` work (the brace form `if -py [ -f x ] {` already did: script._cond only takes `(`); (b) check.py: a parse error on a later line of a block is reported, that line blanked and the file re-read (new `_commands`, `_parse_all`), so the rest of the body stays in its block (no follow-on "unknown command" warnings); a block's closing `}` line now belongs to its span, so an error on a body's last line points at that line. Tests: tests/test_match.py (30). Docs: python-style.md (match section leads, `case -py` as the other spelling, menu, table row, rules, indent message), conditions.md, loops.md (select menu), functions.md (getopts def), examples.md (setup menu), scripting.md, cheatsheet, CHANGELOG (Added + 2 Fixed). Not done: guards, capture patterns / class patterns (a bare word is a glob as in `case -py`); a paren that's never closed inside a block still swallows the rest of the file in `source -n` (reported once, at the block's start).
